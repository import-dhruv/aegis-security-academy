# Chapter 16: Essential Security Research Tools

> **Learning objectives.** Select the right tool for a task; install and run major tools; interpret output; recognize limitations; and use every tool only in authorized contexts.

> **Verification note.** Installation commands and flags change. Always confirm against the official documentation link provided for each tool. Never point scanners at out-of-scope systems.

## 16.1 Tool Categories

- **Interception & Web Testing:** Burp Suite Community/Pro, OWASP ZAP, Caido, mitmproxy, Postman, Insomnia, HTTP Toolkit
- **Network Analysis:** Wireshark, tcpdump, Nmap, Masscan, Netcat (nc)
- **Reconnaissance:** Amass, Subfinder, Assetfinder, httpx, dnsx, Nuclei, Katana, Waybackurls, Gau (GetAllURLs), Feroxbuster, ffuf, Gobuster, WhatWeb, Wappalyzer, Shodan, Censys, SecurityTrails
- **Vulnerability Research:** Semgrep, CodeQL, Gitleaks, Trivy, Grype, Checkov, OWASP Dependency-Check
- **Web Analysis:** Browser Developer Tools, Retire.js, JWT.io, CyberChef, testssl.sh
- **Reverse Engineering:** Ghidra, IDA Free, radare2 / rizin, GDB
- **Reverse Engineering / Mobile:** Frida
- **Mobile Security:** MobSF, JADX, APKTool, Objection, Android Studio Emulator
- **Cloud Security:** Prowler, ScoutSuite, CloudMapper, Pacu, Cloudsplaining

## 16.2 Tool Encyclopedia

Each entry follows the same 13-point structure: purpose, architecture, installation, OS, essential commands, advanced capabilities, output interpretation, example, common mistakes, limitations, alternatives, official documentation, and proficiency level.

### Burp Suite Community/Pro — Interception & Web Testing

- **1. Purpose.** Integrated platform for intercepting, replaying, scanning, and analyzing web traffic.
- **2. Architecture.** Java-based proxy with Proxy, Repeater, Intruder, Scanner (Pro), Sequencer, Decoder, Comparer, Logger; Collaborator for OOB detection.
- **3. Installation.** Download from https://portswigger.net/burp; Community is free, Pro licensed.
- **4. OS compatibility.** Windows, macOS, Linux
- **5. Essential commands.** `Set browser proxy to 127.0.0.1:8080; install CA cert; use Proxy -> Repeater; right-click -> Send to Repeater.`
- **6. Advanced capabilities.** Extensions (BApp Store), macros/session handling, Collaborator, active/passive scan policy tuning.
- **7. Output interpretation.** HTTP history with request/response; issues with confidence/severity; scanner findings.
- **8. Practical example.** Intercept a login in a lab, send to Repeater, change a parameter, observe response differences.
- **9. Common mistakes.** Scanning out-of-scope hosts; not installing CA cert (HTTPS unreadable); trusting scanner results blindly.
- **10. Limitations.** Community lacks active scanner and speed; steep UI learning curve.
- **11. Alternatives.** OWASP ZAP, Caido, mitmproxy
- **12. Official documentation.** https://portswigger.net/burp/documentation
- **13. Recommended proficiency level.** Beginner–Advanced

### OWASP ZAP — Interception & Web Testing

- **1. Purpose.** Free, open-source web application security scanner and intercepting proxy.
- **2. Architecture.** Java proxy with passive/active scanning, spider, fuzzer, AJAX spider, and API; HUD mode.
- **3. Installation.** Download from https://www.zaproxy.org/download/ or install via package manager.
- **4. OS compatibility.** Cross-platform
- **5. Essential commands.** `Set proxy 127.0.0.1:8080; quick start or automated scan; use Spider then Active Scan on a lab.`
- **6. Advanced capabilities.** ZAP API for CI, scripts (Zest, JS), authentication support, context/scope definitions.
- **7. Output interpretation.** Sites tree, Alerts tab with risk levels and CWE mappings, request/response views.
- **8. Practical example.** Run an automated scan against OWASP Juice Shop in a local Docker lab and review alerts.
- **9. Common mistakes.** Scanning without scope; ignoring false positives; using aggressive scan on production.
- **10. Limitations.** Noisy active scan; can disrupt apps; slower than commercial tools.
- **11. Alternatives.** Burp Suite, Caido
- **12. Official documentation.** https://www.zaproxy.org/docs/
- **13. Recommended proficiency level.** Beginner–Intermediate

### Caido — Interception & Web Testing

- **1. Purpose.** Modern web security auditing toolkit with an intercepting proxy and workflow automation.
- **2. Architecture.** Rust-based proxy with a web UI, intercept, replay, search, and a package ecosystem.
- **3. Installation.** Download from https://caido.io/ (free and Pro tiers).
- **4. OS compatibility.** Windows, macOS, Linux
- **5. Essential commands.** `Configure browser proxy; import CA cert; use Match/Replace rules and Replay.`
- **6. Advanced capabilities.** Workflows (visual automation), plugins, project sharing, large request search.
- **7. Output interpretation.** Traffic table with search/filter, replay results, issue tracking.
- **8. Practical example.** Filter traffic by host in a lab and replay a modified request.
- **9. Common mistakes.** Assuming feature parity with Burp; missing CA cert setup.
- **10. Limitations.** Newer ecosystem; fewer extensions than Burp.
- **11. Alternatives.** Burp Suite, OWASP ZAP
- **12. Official documentation.** https://docs.caido.io/
- **13. Recommended proficiency level.** Intermediate

### mitmproxy — Interception & Web Testing

- **1. Purpose.** Interactive, scriptable HTTP/HTTPS intercepting proxy.
- **2. Architecture.** Python-based console proxy (mitmproxy), CLI (mitmdump), and web UI (mitmweb); scripting API.
- **3. Installation.** pip install mitmproxy or see https://mitmproxy.org/.
- **4. OS compatibility.** Cross-platform
- **5. Essential commands.** `mitmproxy -p 8080; set browser proxy; install mitmproxy CA cert.`
- **6. Advanced capabilities.** Python addons to modify traffic automatically; reverse-proxy and upstream modes.
- **7. Output interpretation.** Interactive flow list, request/response detail, script output.
- **8. Practical example.** Write a small addon that adds a header to every request in a lab.
- **9. Common mistakes.** Forgetting CA cert; running scripts against unintended traffic.
- **10. Limitations.** Console UI less beginner-friendly; no active scanner.
- **11. Alternatives.** Burp Suite, HTTP Toolkit
- **12. Official documentation.** https://docs.mitmproxy.org/
- **13. Recommended proficiency level.** Intermediate

### Postman — Interception & Web Testing

- **1. Purpose.** API development and testing client for crafting and organizing requests.
- **2. Architecture.** Electron app with request builder, collections, environments, scripts, and mock servers.
- **3. Installation.** Download from https://www.postman.com/ (free and paid).
- **4. OS compatibility.** Windows, macOS, Linux
- **5. Essential commands.** `Create a request, set method/URL/headers/body, add environment variables, send.`
- **6. Advanced capabilities.** Pre-request/test scripts, collections as code, Newman CLI for CI.
- **7. Output interpretation.** Response body, status, time, headers; test results tab.
- **8. Practical example.** Build a collection of lab API requests with an auth token variable.
- **9. Common mistakes.** Storing real secrets in collections; sending requests to wrong environment.
- **10. Limitations.** Not a security scanner; manual testing tool.
- **11. Alternatives.** Insomnia, curl, HTTPie
- **12. Official documentation.** https://learning.postman.com/
- **13. Recommended proficiency level.** Beginner

- **11. Alternatives.** Postman, curl

### HTTP Toolkit — Interception & Web Testing

- **3. Installation.** Download from https://httptoolkit.com/
- **4. OS compatibility.** Windows, macOS, Linux

- **6. Advanced capabilities.** On-demand mocking, HTTPS interception for mobile via proxy settings.

### Wireshark — Network Analysis

- **1. Purpose.** Graphical network protocol analyzer for deep packet inspection.
- **2. Architecture.** Qt GUI with libpcap capture engine and protocol dissectors; display filters.
- **3. Installation.** Download from https://www.wireshark.org/
- **4. OS compatibility.** Cross-platform
- **5. Essential commands.** `Select interface; start capture; use display filter http or dns; follow TCP stream.`
- **6. Advanced capabilities.** Capture filters (BPF), display filters, statistics, decryption of TLS with keys, Lua plugins.
- **7. Output interpretation.** Packet list, details pane, raw bytes; colored conversations.
- **8. Practical example.** Capture a TCP handshake to a site you own and inspect SYN/SYN-ACK/ACK.
- **9. Common mistakes.** Capturing without permission on shared networks; ignoring sensitive data in captures.
- **10. Limitations.** Large captures consume disk; TLS decryption requires keys.
- **11. Alternatives.** tcpdump, tshark
- **12. Official documentation.** https://www.wireshark.org/docs/
- **13. Recommended proficiency level.** Beginner–Intermediate

### tcpdump — Network Analysis

- **1. Purpose.** Command-line packet capture and filtering tool.
- **2. Architecture.** C library libpcap with Berkeley Packet Filter syntax; CLI output or pcap files.
- **3. Installation.** Usually preinstalled; apt install tcpdump.
- **4. OS compatibility.** Linux, macOS, BSD
- **5. Essential commands.** `tcpdump -i any -nn 'tcp port 80'; tcpdump -w cap.pcap 'icmp'.`
- **6. Advanced capabilities.** BPF filters, -A/-X for payload/hex, ring buffers, reading pcap files with -r.
- **7. Output interpretation.** Line-per-packet text with timestamps, IPs, ports, flags.
- **8. Practical example.** Capture DNS queries from your machine and identify resolver IPs.
- **9. Common mistakes.** Capturing on interfaces you do not own; missing -nn causes slow DNS lookups.
- **10. Limitations.** No protocol dissection like Wireshark; text output is terse.
- **11. Alternatives.** Wireshark, tshark
- **12. Official documentation.** https://www.tcpdump.org/
- **13. Recommended proficiency level.** Intermediate

### Nmap — Network Analysis

- **1. Purpose.** Network discovery and security auditing scanner.
- **2. Architecture.** C/C++ scanner with host discovery, port scan techniques, version/OS detection, NSE scripting.
- **3. Installation.** apt install nmap or https://nmap.org/download.html
- **4. OS compatibility.** Cross-platform
- **5. Essential commands.** `nmap -sV -sC -oA out target  (authorized targets only).`
- **6. Advanced capabilities.** NSE scripts, -A aggressive, timing templates (-T0..-T5), IPv6 (-6), OS detection (-O).
- **7. Output interpretation.** Port table with states, services, versions; XML/normal/grepable outputs.
- **8. Practical example.** Scan your own lab VM and compare -sS vs -sT results.
- **9. Common mistakes.** Scanning third parties; overly aggressive timing; misreading filtered as closed.
- **10. Limitations.** Noisy; blocked by firewalls; OS detection needs privileged access.
- **11. Alternatives.** Masscan, Naabu, rustscan
- **12. Official documentation.** https://nmap.org/book/man.html
- **13. Recommended proficiency level.** Intermediate

### Masscan — Network Analysis

- **1. Purpose.** Extremely fast TCP port scanner using asynchronous transmission.
- **2. Architecture.** C scanner with custom TCP stack; can scan large ranges quickly.
- **3. Installation.** apt install masscan or build from https://github.com/robertdavidgraham/masscan
- **4. OS compatibility.** Linux, BSD (limited Windows support)
- **5. Essential commands.** `masscan 10.0.0.0/24 -p80,443 --rate 1000 (owned ranges only).`
- **6. Advanced capabilities.** Banner grabbing, output to JSON/XML, exclusion lists.
- **7. Output interpretation.** Discovered open ports with banners.
- **8. Practical example.** Scan your own isolated lab network and compare speed to Nmap.
- **9. Common mistakes.** Extreme noise; high risk on shared networks; easy to cause disruption.
- **10. Limitations.** Requires careful rate limiting; no version detection; may overwhelm networks.
- **11. Alternatives.** Nmap, Naabu
- **12. Official documentation.** https://github.com/robertdavidgraham/masscan
- **13. Recommended proficiency level.** Advanced

### Netcat (nc) — Network Analysis

- **1. Purpose.** Network utility for reading/writing data over TCP/UDP.
- **2. Architecture.** Simple CLI using sockets; can listen, connect, and transfer files.
- **3. Installation.** Usually preinstalled (ncat from Nmap is an alternative).
- **4. OS compatibility.** Cross-platform
- **5. Essential commands.** `nc -lvnp 4444 (listen); nc host 80 (connect).`
- **6. Advanced capabilities.** Reverse/bind shells in labs, file transfer, banner grabbing, port checks.
- **7. Output interpretation.** Raw stream output in terminal.
- **8. Practical example.** Use nc to request a file from a local lab server and capture the response.
- **9. Common mistakes.** Using it for unauthorized access; leaving listeners open.
- **10. Limitations.** No encryption; no authentication; raw and error-prone.
- **11. Alternatives.** ncat, socat, curl
- **12. Official documentation.** https://nmap.org/ncat/
- **13. Recommended proficiency level.** Intermediate

### Amass — Reconnaissance

- **1. Purpose.** Attack surface mapping and subdomain discovery.
- **2. Architecture.** Go tool with configurable data sources and a graph data model.
- **3. Installation.** go install github.com/owasp-amass/amass/v4/...@latest
- **4. OS compatibility.** Cross-platform
- **5. Essential commands.** `amass enum -passive -d example.com -o subs.txt.`
- **6. Advanced capabilities.** Active enumeration, API integrations, data source configuration in YAML.
- **7. Output interpretation.** Subdomain lists, JSON, graphDB outputs.
- **8. Practical example.** Enumerate subdomains of a domain you own; compare passive vs active (authorized) results.
- **9. Common mistakes.** API keys needed for full coverage; active mode can be noisy and out of scope.
- **10. Limitations.** Data source availability changes; rate limits on free APIs.
- **11. Alternatives.** Subfinder, Assetfinder
- **12. Official documentation.** https://github.com/owasp-amass/amass
- **13. Recommended proficiency level.** Intermediate

### Subfinder — Reconnaissance

- **1. Purpose.** Fast passive subdomain discovery.
- **2. Architecture.** Go tool with many passive source modules; configurable providers.
- **3. Installation.** go install github.com/projectdiscovery/subfinder/v2/cmd/subfinder@latest
- **4. OS compatibility.** Cross-platform
- **5. Essential commands.** `subfinder -d example.com -o subs.txt.`
- **6. Advanced capabilities.** Multiple resolvers, sources config, JSON output, rate limiting.
- **7. Output interpretation.** One subdomain per line; deduplicated.
- **8. Practical example.** Enumerate your own domain and deduplicate against CT log results.
- **9. Common mistakes.** Assuming results are complete; using it on out-of-scope domains.
- **10. Limitations.** Passive only; source coverage varies.
- **11. Alternatives.** Amass, Assetfinder, oneforall
- **12. Official documentation.** https://github.com/projectdiscovery/subfinder
- **13. Recommended proficiency level.** Beginner–Intermediate

### Assetfinder — Reconnaissance

- **1. Purpose.** Find domains/subdomains related to a target using public sources.
- **2. Architecture.** Go tool querying certificate transparency and other public datasets.
- **3. Installation.** go install github.com/tomnomnom/assetfinder@latest
- **4. OS compatibility.** Cross-platform
- **5. Essential commands.** `assetfinder --subs-only example.com > subs.txt.`
- **6. Advanced capabilities.** Combine with httpx/dnsx in pipelines.
- **7. Output interpretation.** Plain list of domains.
- **8. Practical example.** Compare with subfinder output for a domain you own.
- **9. Common mistakes.** Public data only; may include unrelated domains.
- **10. Limitations.** Limited sources; no validation of liveness.
- **11. Alternatives.** Subfinder, Amass
- **12. Official documentation.** https://github.com/tomnomnom/assetfinder
- **13. Recommended proficiency level.** Beginner

### httpx — Reconnaissance

- **1. Purpose.** Fast HTTP toolkit for probing live hosts and extracting metadata.
- **2. Architecture.** Go tool with concurrent requests and configurable probes.
- **3. Installation.** go install github.com/projectdiscovery/httpx/cmd/httpx@latest
- **4. OS compatibility.** Cross-platform
- **5. Essential commands.** `httpx -l subs.txt -status-code -title -tech-detect -o live.txt.`
- **6. Advanced capabilities.** Probe paths, custom headers, TLS info, rate limiting, JSON output.
- **7. Output interpretation.** Each line: URL, status, title, tech, content length.
- **8. Practical example.** Probe a list of your own subdomains and sort by status code.
- **9. Common mistakes.** High concurrency against unauthorized targets; ignoring rate limits.
- **10. Limitations.** Only probes; does not exploit.
- **11. Alternatives.** curl (manual), httpprobe
- **12. Official documentation.** https://github.com/projectdiscovery/httpx
- **13. Recommended proficiency level.** Beginner–Intermediate

### dnsx — Reconnaissance

- **1. Purpose.** Fast DNS toolkit for querying and filtering DNS data.
- **2. Architecture.** Go tool using configurable resolvers and question types.
- **3. Installation.** go install github.com/projectdiscovery/dnsx/cmd/dnsx@latest
- **4. OS compatibility.** Cross-platform
- **5. Essential commands.** `dnsx -l subs.txt -a -cname -resp -o dns.txt.`
- **6. Advanced capabilities.** Wildcard filtering, custom resolvers, JSON, extract records.
- **7. Output interpretation.** Resolved records per host.
- **8. Practical example.** Resolve your own subdomains and identify wildcard DNS behavior.
- **9. Common mistakes.** Using unreliable public resolvers; misinterpreting NXDOMAIN.
- **10. Limitations.** DNS only; no HTTP validation.
- **11. Alternatives.** dig, adig
- **12. Official documentation.** https://github.com/projectdiscovery/dnsx
- **13. Recommended proficiency level.** Intermediate

### Nuclei — Reconnaissance

- **1. Purpose.** Template-based vulnerability scanner with a large community template library.
- **2. Architecture.** Go engine executing YAML templates for HTTP, DNS, TCP, and more.
- **3. Installation.** go install github.com/projectdiscovery/nuclei/v3/cmd/nuclei@latest
- **4. OS compatibility.** Cross-platform
- **5. Essential commands.** `nuclei -u https://target -t templates/ (authorized targets only).`
- **6. Advanced capabilities.** Custom templates, severity filtering, OOB via interactsh, rate limiting.
- **7. Output interpretation.** Findings with template ID, severity, matched request/response.
- **8. Practical example.** Write a simple template that checks for a header on your own lab server.
- **9. Common mistakes.** Running all templates without scope; high request volume; false positives.
- **10. Limitations.** Template quality varies; not a replacement for manual testing.
- **11. Alternatives.** Nessus, OpenVAS, custom scripts
- **12. Official documentation.** https://nuclei.projectdiscovery.io/
- **13. Recommended proficiency level.** Intermediate

### Katana — Reconnaissance

- **1. Purpose.** Web crawler that discovers endpoints, including from JavaScript.
- **2. Architecture.** Go crawler with headless browser support for JS-heavy apps.
- **3. Installation.** go install github.com/projectdiscovery/katana/cmd/katana@latest
- **4. OS compatibility.** Cross-platform
- **5. Essential commands.** `katana -u https://target -o urls.txt (authorized).`
- **6. Advanced capabilities.** Headless mode (-headless), scope control, custom headers, form filling.
- **7. Output interpretation.** Crawled URLs and discovered endpoints.
- **8. Practical example.** Crawl your own SPA and list endpoints only discoverable via JS.
- **9. Common mistakes.** Over-crawling; hitting logout or state-changing links; missing auth context.
- **10. Limitations.** Can be noisy; may miss client-side routes.
- **11. Alternatives.** gospider, Hakrawler
- **12. Official documentation.** https://github.com/projectdiscovery/katana
- **13. Recommended proficiency level.** Intermediate

### Gau (GetAllURLs) — Reconnaissance

- **12. Official documentation.** https://github.com/lc/gau

### Feroxbuster — Reconnaissance

- **1. Purpose.** Recursive content discovery (directories/files).
- **2. Architecture.** Rust tool with recursion, filters, and wildcard detection.
- **3. Installation.** apt/cargo install or https://github.com/epi052/feroxbuster
- **4. OS compatibility.** Cross-platform
- **5. Essential commands.** `feroxbuster -u https://target -w wordlist.txt (authorized).`
- **6. Advanced capabilities.** Auto-filtering 404s, recursion depth, rate limits, proxy support.
- **7. Output interpretation.** Discovered paths with status, size, and response time.
- **8. Practical example.** Discover hidden directories on a local DVWA instance.
- **9. Common mistakes.** High volume; scanning out of scope; recursive blow-up.
- **10. Limitations.** Noisy; false positives with catch-all responses.
- **11. Alternatives.** ffuf, Gobuster, DirBuster
- **12. Official documentation.** https://github.com/epi052/feroxbuster
- **13. Recommended proficiency level.** Intermediate

### ffuf — Reconnaissance

- **1. Purpose.** Fast web fuzzer for paths, parameters, hosts, and values.
- **2. Architecture.** Go fuzzer with keyword substitution (FUZZ) and rich filters/matchers.
- **3. Installation.** go install github.com/ffuf/ffuf/v2@latest
- **4. OS compatibility.** Cross-platform
- **5. Essential commands.** `ffuf -u https://target/FUZZ -w wordlist.txt -mc 200,301.`
- **6. Advanced capabilities.** Multiple keyword positions, recursive mode, filter by size/time, JSON output.
- **7. Output interpretation.** Matched requests with status/size/time.
- **8. Practical example.** Fuzz a parameter name on your own lab app and inspect interesting sizes.
- **9. Common mistakes.** Unbounded speed; hitting state-changing endpoints; ignoring rate limits.
- **10. Limitations.** Requires careful filter tuning; noisy.
- **11. Alternatives.** Feroxbuster, Gobuster, wfuzz
- **12. Official documentation.** https://github.com/ffuf/ffuf
- **13. Recommended proficiency level.** Intermediate

### Gobuster — Reconnaissance

- **1. Purpose.** Directory, DNS, and vhost brute-forcing tool.
- **2. Architecture.** Go tool with separate modes (dir, dns, vhost) and wordlist support.
- **3. Installation.** apt install gobuster or go install github.com/OJ/gobuster/v3@latest
- **4. OS compatibility.** Cross-platform
- **5. Essential commands.** `gobuster dir -u https://target -w wordlist.txt.`
- **6. Advanced capabilities.** TLS, extensions, status filtering, vhost and dns modes.
- **7. Output interpretation.** Discovered names with status codes.
- **8. Practical example.** Enumerate vhosts on your own lab server.
- **9. Common mistakes.** Scanning without authorization; default wordlists cause noise.
- **10. Limitations.** Simpler than ffuf; no recursive crawling by default.
- **11. Alternatives.** ffuf, Feroxbuster
- **12. Official documentation.** https://github.com/OJ/gobuster
- **13. Recommended proficiency level.** Beginner–Intermediate

- **11. Alternatives.** Wappalyzer, BuiltWith
- **12. Official documentation.** https://github.com/urbanadventurer/WhatWeb
- **13. Recommended proficiency level.** Beginner
