# Chapter 5: Python for Cybersecurity

> **Learning objectives.** Write correct Python for security tasks; work with data structures, regex, files, JSON/XML, HTTP, sockets, concurrency, and APIs; and build the practical utilities described at the end of this chapter — all against owned or lab targets.

## 5.1 Why Python

Python is the lingua franca of security tooling because it is readable, has a vast standard library, and an ecosystem of security libraries (`requests`, `scapy`, `cryptography`, `beautifulsoup4`, etc.). Its weaknesses — speed and runtime dependencies — matter less for orchestration and analysis than for exploit payloads.

Setup: use Python 3.11+, virtual environments (Chapter 3), and an editor with linting. Format with `black`, lint with `ruff`, type-check with `mypy`. Clean code is easier to trust when it is validating a security finding.

## 5.2 Fundamentals

```python
# Data types
name: str = "alice"
age: int = 30
ratio: float = 0.75
active: bool = True
items: list[str] = ["a", "b"]
meta: dict[str, int] = {"port": 80}
tags: set[str] = {"web", "api"}

# Control flow
for i in range(5):
    if i % 2 == 0:
        continue
    print(i)

while age < 40:
    age += 1

# Functions with type hints
def classify(status: int) -> str:
    if 200 <= status < 300:
        return "success"
    elif 400 <= status < 500:
        return "client-error"
    return "other"
```

Strings, lists, dicts, sets, and tuples each have trade-offs. Dicts give O(1) average lookup; lists give O(n) search. Choosing the right structure is both a performance and a security decision (e.g., a list-based membership check in a hot path can become a DoS).

**Exception handling** keeps tools robust:

```python
try:
    r = requests.get(url, timeout=5)
    r.raise_for_status()
except requests.Timeout:
    print("timeout")
except requests.RequestException as e:
    print(f"request failed: {e}")
finally:
    print("done")
```

Always set timeouts on network calls. Never catch bare `except:` and silently continue in security code — swallowed errors produce false negatives.

**Object-oriented programming** organizes larger tools:

```python
class Finding:
    def __init__(self, title: str, severity: str):
        self.title = title
        self.severity = severity

    def __repr__(self) -> str:
        return f"<Finding {self.title} [{self.severity}]>"
```

## 5.3 Regular Expressions

Regexes match patterns in text — essential for parsing logs, responses, and configurations.

```python
import re
pattern = re.compile(r"(?i)server:\s*([^\r\n]+)")
m = pattern.search("Server: nginx/1.24")
print(m.group(1))  # nginx/1.24
```

Key constructs: `.` (any char), `*` `+` `?` (quantifiers), `{n,m}`, `[abc]` (classes), `\d` `\w` `\s`, `^` `$` (anchors), `(...)` (groups), `|` (alternation), non-greedy `*?`.

> **Warning — ReDoS.** Naive regexes with nested quantifiers (e.g., `(a+)+$`) can exhibit catastrophic backtracking: exponential time on attacker-controlled input. This is a real denial-of-service class. Prefer simple patterns, anchor them, avoid nested ambiguity, and use timeouts or linear-time engines when parsing untrusted data.

## 5.4 Files, JSON, and XML

```python
import json, csv, pathlib
data = json.loads('{"host": "lab", "ports": [80, 443]}')
print(data["ports"][0])
pathlib.Path("out.json").write_text(json.dumps(data, indent=2))
```

- Use `json`, never `eval`, to parse untrusted structured data.
- **XML** parsing is risky: external entity expansion can cause XXE. Use hardened parsers (`defusedxml`) and disable entity resolution.
- YAML: use `yaml.safe_load`, not `yaml.load`, to avoid arbitrary object construction.
- Handle encodings explicitly (`encoding="utf-8"`).

## 5.5 HTTP Requests

The `requests` library is the workhorse:

```python
import requests
s = requests.Session()
s.headers.update({"User-Agent": "ResearchTool/1.0"})
r = s.get("https://lab.local/", timeout=10, allow_redirects=False)
print(r.status_code, r.headers.get("Server"))
print(r.cookies.get_dict())
```

Important parameters: `params`, `data`, `json`, `headers`, `cookies`, `timeout`, `allow_redirects`, `verify` (TLS verification — keep it on), `proxies` (to route through Burp/ZAP in a lab). Handle status codes, rate limits, and `Retry-After`. Respect `robots.txt` and, more importantly, program rules.

## 5.6 Socket Programming

```python
import socket
s = socket.socket(socket.AF_INET, socket.SOCK_STREAM)
s.settimeout(1)
result = s.connect_ex(("127.0.0.1", 80))  # 0 means open
print("open" if result == 0 else "closed")
s.close()
```

`connect_ex` avoids exceptions for closed ports. Threads or `asyncio` let you scan many ports efficiently — but only on authorized targets. Understand TCP states (Chapter 4) to interpret results.

## 5.7 Concurrency

- **Multithreading** (`threading`, `concurrent.futures.ThreadPoolExecutor`) suits I/O-bound work like network scanning.
- **Multiprocessing** (`multiprocessing`) suits CPU-bound work (e.g., hashing) because it bypasses the GIL.
- **Async** (`asyncio` + `aiohttp`) handles many concurrent connections in one thread.

```python
from concurrent.futures import ThreadPoolExecutor

def probe(port):
    ...

with ThreadPoolExecutor(max_workers=50) as ex:
    results = list(ex.map(probe, range(1, 1025)))
```

Bound concurrency: too many workers causes socket exhaustion, rate-limit triggers, and unreliable results — and against real targets could constitute a DoS.

## 5.8 APIs and Web Scraping

Use official APIs when available. For HTML, parse with BeautifulSoup rather than regex:

```python
from bs4 import BeautifulSoup
soup = BeautifulSoup(html, "html.parser")
for form in soup.find_all("form"):
    print(form.get("action"), [i.get("name") for i in form.find_all("input")])
```

This is the basis of endpoint discovery in authorized applications. Respect access controls, authentication, and rate limits; never scrape personal data.

## 5.10 Practical Projects (Build Each in a Lab)

### Project 1: HTTP Security Header Analyzer

**Goal:** given a URL you own, report which security headers are present and whether they are well configured.

```python
import requests
HEADERS = ["Content-Security-Policy", "Strict-Transport-Security",
           "X-Content-Type-Options", "X-Frame-Options", "Referrer-Policy"]

def analyze(url):
    r = requests.get(url, timeout=10)
    for h in HEADERS:
        v = r.headers.get(h)
        print(f"{h}: {v if v else 'MISSING'}")

analyze("http://127.0.0.1:3000")  # local Juice Shop
```

Extend with checks: `X-Frame-Options` value, HSTS max-age, cookie flags. Output JSON for reporting.

### Project 2: URL Parser

Use `urllib.parse.urlparse` to split scheme, host, path, query, and fragment; enumerate parameters; detect duplicate parameters and encoded characters.

### Project 3: DNS Lookup Utility

Wrap `dnspython` to query A, AAAA, CNAME, MX, TXT, NS; accept a domain you own; print a table.

### Project 4: Log Analyzer

Parse an access log (Apache/NGINX combined format) with regex; count status codes, top IPs, 404s, and suspicious user agents; chart with a simple counter.

### Project 5: Local Port Scanner

Build the threaded scanner above; restrict input to `127.0.0.1` or lab IPs; emit a CSV. Add OS detection only via banner grabbing in your own lab.

### Project 6: Subdomain Enumeration (Authorized Datasets)

Given a list of subdomains from certificate transparency or a provided dataset, resolve each with `dnspython`, deduplicate, and mark live HTTP hosts with `httpx`. Only for domains you own or are authorized to test.

### Project 7: Security Header Checker (CI Version)

Turn Project 1 into a CLI that exits nonzero when required headers are missing; integrate into a local CI pipeline for your own app.

### Project 8: Basic Vulnerability Verification Utility

Create a tool that takes a URL and a known test marker, checks whether a reflected parameter appears unescaped in the HTML, and reports a *candidate* XSS — with a clear warning that human verification in an authorized lab is required. Never point it at third-party systems.

## 5.11 Common Mistakes

1. Missing timeouts → hangs.
2. Disabling TLS verification (`verify=False`) → meaningless results and security risk.
3. Using regex on HTML → brittle parsing.
4. Unbounded concurrency → self-inflicted DoS.
5. Trusting redirects to stay in scope → always check final URL.
6. Not encoding parameters → broken or unintended requests.

## 5.12 Key Takeaways

- Python's standard library plus a few packages cover almost every security scripting need.
- Parse structured data with proper libraries; avoid `eval`, unsafe YAML/XML, and fragile regexes on markup.
- Network code needs timeouts, bounded concurrency, and explicit error handling.
- The projects build a personal toolkit and a portfolio — keep them in GitHub with clear READMEs.
