## 34.1 Foundational Questions

Foundational questions: computer science, Linux, security concepts, tools, and core terminology.

**Q1.** What is the difference between information security and cybersecurity?
**Answer.** Information security is the broad discipline of protecting information in any medium (paper, digital, verbal), while cybersecurity is the subset concerned with digital systems, networks, and cyberspace. In modern practice the terms overlap heavily; the useful distinction is that InfoSec is broader and predates computing.

**Q2.** Define the CIA triad and give one example failure for each property.
**Answer.** Confidentiality: only authorized parties can access data; failure is a data breach. Integrity: data is accurate and unmodified without detection; failure is an attacker altering a transaction. Availability: systems are accessible when needed; failure is a DDoS or ransomware outage.

**Q3.** What is the risk equation and why is perfect security impossible?
**Answer.** Risk is approximately threat likelihood multiplied by impact, reduced by effective controls. Perfect security is impossible because controls cost money and reduce usability, threats evolve, and new vulnerabilities appear; the goal is risk management and resilience, not absolute safety.

**Q4.** Explain why two's complement matters for security.
**Answer.** Fixed-width signed integers wrap around: adding 1 to the largest 32-bit signed integer yields the most negative value. This integer overflow can produce undersized allocations or bypass bounds checks, so it is a root cause of memory and logic vulnerabilities.

**Q5.** Convert 0x1F to decimal and explain why hexadecimal is used.
**Answer.** 0x1F = 1*16 + 15 = 31. Hex is used because each digit maps exactly to four bits, making binary data such as addresses and byte sequences compact and readable.

**Q6.** What is the difference between a process and a thread?
**Answer.** A process is an instance of a running program with its own address space and resources; a thread is a unit of execution within a process sharing that address space. Threads are cheaper to switch but shared state introduces race conditions.

**Q7.** Explain user mode vs. kernel mode and why the boundary matters.
**Answer.** User mode restricts hardware and memory access; kernel mode has full privileges. System calls provide a controlled transition. The boundary is a security control: kernel bugs can break isolation, so drivers and kernel code are a high-value target.

**Q8.** What is virtual memory and what security property does it provide?
**Answer.** Virtual memory gives each process a private address space translated by the MMU to physical memory via page tables. It provides isolation between processes and page-level permissions, forming the basis of process sandboxes.

**Q9.** Describe the stack and heap and one vulnerability associated with each.
**Answer.** The stack holds function frames, locals, and return addresses and grows downward; overflowing it can overwrite the return address. The heap holds dynamic allocations; errors there produce use-after-free, double-free, and heap overflows.

**Q10.** What is a system call? Give three examples.
**Answer.** A system call is the controlled interface from user programs to the kernel. Examples on Linux include open (files), sendto (network), and mmap (memory mapping).

**Q11.** Why is Big-O notation relevant to security?
**Answer.** Complexity describes how resource use grows with input size. A parser that is O(n^2) or a regex with catastrophic backtracking can be turned into a denial-of-service vector by a large or crafted input.

**Q12.** What are setuid binaries and why are they security-sensitive?
**Answer.** Setuid is a Unix permission bit that runs a program with the file owner's privileges, often root. A flaw in such a program can yield local privilege escalation, so they are carefully audited.

**Q13.** What is the difference between a compiler and an interpreter?
**Answer.** A compiler translates source to machine code or bytecode ahead of execution; an interpreter executes source statements directly at runtime. Bytecode VMs combine the two by compiling to portable intermediate code.

**Q14.** Explain the fetch-decode-execute cycle.
**Answer.** The CPU fetches the next instruction addressed by the program counter, decodes it, executes it, and repeats. Pipelining and speculative execution optimize this cycle and introduce side-channel considerations.

**Q15.** What is a cache and how can it leak information?
**Answer.** A cache is small fast memory close to the CPU that exploits locality. Access patterns affect cache state and timing, enabling cache-timing side channels that can reveal secrets such as keys.

**Q16.** What is a pointer and why are pointer bugs dangerous in C?
**Answer.** A pointer holds a memory address. C permits unchecked pointer arithmetic, so an incorrect offset can read or write arbitrary memory, producing memory-corruption vulnerabilities.

**Q17.** What is undefined behavior and why does it matter for security?
**Answer.** Undefined behavior is an operation the language standard does not define, such as signed overflow in C. Compilers may assume it never occurs and optimize accordingly, turning seemingly harmless bugs into exploitable conditions.

**Q18.** What are capabilities in Linux and how do they differ from root?
**Answer.** Capabilities divide root's privileges into fine-grained units such as CAP_NET_RAW. They allow a process to have only the privileges it needs, reducing the impact of compromise.

**Q19.** What are Linux namespaces and cgroups used for?
**Answer.** Namespaces isolate kernel resources such as PID, network, and mounts; cgroups limit and account for resource usage. Together they form the basis of containers.

**Q20.** Which Linux files contain user account and password hash information?
**Answer.** /etc/passwd stores account metadata and /etc/shadow stores password hashes with root-only permissions. /etc/group stores groups and /etc/sudoers defines sudo policy.

**Q21.** What does `ss -tulpn` show?
**Answer.** It lists listening TCP/UDP sockets, numeric addresses, and the owning processes, replacing the older netstat tool for socket inspection.

**Q22.** What is the purpose of umask?
**Answer.** Umask sets default permission bits for newly created files and directories by masking out bits. A weak umask can create world-writable files, a security hazard.

**Q23.** Why must security tools set timeouts on network calls?
**Answer.** Without timeouts, a non-responsive host or blocked connection can hang indefinitely, producing unreliable results and potentially unbounded resource use.

**Q24.** What is the difference between multithreading and multiprocessing in Python?
**Answer.** Multithreading suits I/O-bound work but is limited by the GIL for CPU-bound tasks; multiprocessing uses separate processes to bypass the GIL for CPU-bound work at the cost of memory and IPC.

**Q25.** Why should you use parameterized queries rather than string concatenation?
**Answer.** Parameterized queries pass data separately from the SQL statement so input cannot change the query's structure, eliminating SQL injection. Concatenation treats input as part of the code.

**Q26.** What is a hash table and what is hash-flooding DoS?
**Answer.** A hash table maps keys to values using a hash function. If an attacker sends many keys that collide, lookups degrade to linear time, consuming CPU and causing denial of service.

**Q27.** What does a setuid root binary imply for an attacker who finds a flaw in it?
**Answer.** Because it runs with root privileges, a memory-corruption or logic flaw can be escalated into full root access — a classic local privilege escalation path.

**Q28.** What is a symbolic link and what risk can it create?
**Answer.** A symlink is a file that points to another path. If a privileged process follows a symlink in a user-writable directory, it may read or overwrite a sensitive file (a symlink attack).

**Q29.** What is the difference between confidentiality, authentication, and non-repudiation?
**Answer.** Confidentiality hides data from unauthorized parties; authentication verifies identity; non-repudiation provides evidence that an actor performed an action, usually via signatures and logs.

**Q30.** Why do security researchers need to understand assembly language?
**Answer.** Assembly reveals what a binary actually does without source, including compiler transformations, validation checks, and exploitable constructs. It is essential for reverse engineering and binary exploitation.

## 34.2 Web Questions

Web security questions: OWASP, injection, XSS, authorization, sessions, and modern web flaws.

**Q1.** What is the root cause of SQL injection and how do you prevent it?
**Answer.** Untrusted data is concatenated into a query so it is interpreted as SQL code. Prevention uses parameterized queries or prepared statements, allow-lists for dynamic identifiers, and least-privilege database accounts.

**Q2.** Explain the three main types of XSS and the key difference between them.
**Answer.** Reflected XSS: payload appears in the request and is echoed in the response. Stored XSS: payload is persisted and served to other users. DOM XSS: client-side JavaScript writes untrusted data into a dangerous sink. The difference is where the payload travels and when it is rendered.

**Q3.** Why does `textContent` avoid XSS where `innerHTML` does not?
**Answer.** textContent creates a text node, so markup characters are displayed literally. innerHTML parses its argument as HTML, so injected tags and event handlers become executable code.

**Q4.** What is CSRF and how do anti-CSRF tokens stop it?
**Answer.** CSRF makes a victim's browser send an unwanted state-changing request using ambient cookies. A secret per-session or per-request token that the attacker cannot obtain must accompany such requests; SameSite cookies and Origin checks add defense.

**Q5.** Explain SSRF and name two defenses.
**Answer.** SSRF makes a server fetch an attacker-chosen URL, potentially reaching internal services or cloud metadata. Defenses: strict allow-lists of hosts/schemes/ports and blocking private/link-local IP ranges, plus disabling redirects and egress controls.

**Q6.** What is BOLA/IDOR and how do you validate it safely?
**Answer.** It is accessing another user's object by changing an identifier without an ownership check. Validate with two accounts you control: use account A's token to access account B's object ID and observe whether it succeeds, using only synthetic data.

**Q7.** What distinguishes BFLA from BOLA?
**Answer.** BOLA is object-level: accessing a resource you should not. BFLA is function-level: invoking an endpoint or action (often administrative) that your role should not permit.

**Q8.** Why are business logic vulnerabilities hard for scanners to find?
**Answer.** They depend on intended workflow semantics, not malformed input. A scanner does not understand that a negative quantity or out-of-order step is invalid for that business process.

**Q9.** Explain HTTP request smuggling in one paragraph.
**Answer.** Front-end and back-end servers disagree on where a request ends, typically due to conflicting Content-Length and Transfer-Encoding headers or different parsers. An attacker prepends a second request the backend executes, enabling request hijacking or ACL bypass.

**Q10.** What causes a web cache poisoning vulnerability?
**Answer.** A response reflects an attacker-controlled input such as a header, but that input is not part of the cache key. A poisoned response is stored and served to other users who do not send the header.

**Q11.** How does SameSite cookie attribute mitigate CSRF?
**Answer.** SameSite=Lax or Strict prevents cookies from being sent on cross-site requests, so a malicious site cannot authenticate a forged request. None requires Secure and offers no CSRF protection.

**Q12.** What is CORS misconfiguration that allows account takeover?
**Answer.** Reflecting arbitrary origins together with Access-Control-Allow-Credentials: true allows any site to make authenticated cross-origin reads, enabling theft of sensitive data or CSRF-token retrieval.

**Q13.** Why is `HttpOnly` useful but insufficient against XSS?
**Answer.** HttpOnly prevents JavaScript from reading the cookie, limiting direct session theft. XSS can still act within the victim's session (perform requests, read CSRF tokens), so output encoding and CSP remain necessary.

**Q14.** What is prototype pollution and how does it lead to authorization bypass?
**Answer.** Unsafe deep merges copy attacker-controlled `__proto__` keys into Object.prototype. If downstream code checks properties like `isAdmin` on objects that inherit from the polluted prototype, the attacker can make the check succeed.

**Q15.** What is a race condition (TOCTOU) in web applications?
**Answer.** A check and its use are separate operations; concurrent requests can both pass the check before either updates state, e.g., redeeming a one-time coupon twice. Fix with atomic transactions and idempotency keys.

**Q16.** What is XXE and what is the primary fix?
**Answer.** An XML parser resolves external entities declared in a DOCTYPE, allowing local file reads and SSRF. Disable DTDs and external entity processing in the parser configuration.

**Q17.** Why is file upload a high-risk feature?
**Answer.** If validation is weak, an attacker can upload executable content (e.g., a webshell) into a directory where the server executes it, or use path traversal/polyglots. Fix with allow-lists, magic-byte checks, renaming, and storage outside the web root.

**Q18.** What is a path traversal attack?
**Answer.** Using `../` sequences or encoded variants in a path parameter to escape the intended directory and read or write arbitrary files. Defenses: canonicalize paths and verify they remain under a base directory.

**Q19.** What is insecure deserialization and which languages are most affected?
**Answer.** Deserializing untrusted data can instantiate classes and trigger gadget chains leading to RCE. Java, .NET, PHP, and Python pickle are common examples. Use data-only formats with strict schemas.

**Q20.** What is SSTI and give a safe detection marker.
**Answer.** Server-side template injection occurs when user input is concatenated into a template source before rendering. In a lab, `{{7*7}}` reflecting `49` indicates evaluation. Fix by using static templates with parameters.

**Q21.** What is an open redirect and how can it chain to greater impact?
**Answer.** A parameter controls a redirect target without validation. It can be chained with OAuth to leak tokens via the redirect, or used for phishing. Use relative-path or origin allow-lists.

**Q22.** What is host header injection?
**Answer.** An application trusts the untrusted Host header to generate links or make security decisions. A poisoned Host can produce reset-password links pointing to an attacker's server. Use a configured canonical origin.

**Q23.** What is subdomain takeover?
**Answer.** A dangling DNS record points to an external service that is no longer claimed; an attacker claims it and serves content on the organization's subdomain. Fix by removing stale records during deprovisioning.

**Q24.** How does a strict CSP mitigate XSS?
**Answer.** CSP restricts which origins may load scripts and disallows inline scripts unless protected by a nonce or hash. Even if HTML injection occurs, the browser refuses to execute unauthorized script.

**Q25.** What is HTTP parameter pollution?
**Answer.** Supplying duplicate parameters with the same name; different frameworks and proxies select the first, last, or all values. This can bypass validation applied to one value while another is used.

**Q26.** Why are verbose error messages a security issue?
**Answer.** They can reveal stack traces, SQL fragments, file paths, versions, and framework details, accelerating an attacker's reconnaissance and exploitation.

**Q27.** What is the difference between authentication and authorization failures?
**Answer.** Authentication failures let an attacker impersonate a user (e.g., bypass login or forge a token). Authorization failures let a legitimate user perform actions beyond their permissions (BOLA/BFLA).

**Q28.** Which OWASP Top 10:2025 category covers SSRF now?
**Answer.** SSRF was folded into A01 Broken Access Control in the 2025 edition; in 2021 it was a separate A10 category.

**Q29.** What is a mass assignment vulnerability?
**Answer.** When request fields are bound directly to object properties, an attacker can set fields the developer did not intend, such as `role=admin`. Use explicit allow-lists of writable fields.

**Q30.** What is the difference between reflected and stored XSS in terms of impact?
**Answer.** Stored XSS is typically more severe because it executes for every user who views the persisted content without requiring them to click a crafted link; reflected XSS usually needs victim interaction.

**Q31.** What is a same-origin policy and why does it matter?
**Answer.** SOP forbids a page from one origin (scheme, host, port) from reading content of another origin. It is the foundation of browser isolation; CORS and postMessage are controlled relaxations.

**Q32.** Why should dynamic identifiers in SQL be allow-listed?
**Answer.** Parameters can bind values but not identifiers such as column names. Dynamic ORDER BY or table names must be chosen from a fixed allow-list to prevent injection.

**Q33.** What is cache deception?
**Answer.** Tricking a cache into storing a personalized response by making its URL look static, so other users receive content intended for one user. Fix with careful Cache-Control rules and URL design.

**Q34.** What is a blind SQL injection and how is it detected?
**Answer.** No query results or errors are returned; the attacker infers truth by observing behavioral differences (boolean-based) or timing delays (time-based). Detection uses controlled markers in a lab.

**Q35.** How can OAuth state and PKCE prevent common attacks?
**Answer.** State ties the authorization response to the initiating session, preventing CSRF on the callback. PKCE binds the code to a client-generated verifier, preventing code interception, especially for public clients.

**Q36.** What is the danger of accepting `alg:none` in JWT verification?
**Answer.** It allows an attacker to submit an unsigned token that the server accepts, bypassing authentication. Verifiers must pin allowed algorithms and require a valid signature.

**Q37.** What is a prototype pollution gadget?
**Answer.** Downstream code that reads a property inherited from a polluted prototype, such as an authorization flag or configuration value, turning the pollution into a concrete impact.

**Q38.** Why is comparing roles with two test accounts effective?
**Answer.** Many authorization flaws are invisible from a single account. Comparing what user A can do to A's and B's objects reveals object-level and function-level gaps systematically.

**Q187.** Explain encapsulation across the TCP/IP layers.
**Answer.** Application data receives a transport header (TCP segment), then an IP header (packet), then a link-layer header (frame), and finally becomes bits on the medium. Each receiving layer strips its corresponding header.

**Q188.** What is ARP and why is it insecure?
**Answer.** ARP maps IPv4 addresses to MAC addresses on a local network. It has no authentication, so forged replies can redirect traffic through an attacker (ARP spoofing).

**Q189.** Given 192.168.1.0/26, what is the usable host range?
**Answer.** /26 leaves 6 host bits: 64 addresses total, network .0, broadcast .63, usable .1 through .62.

**Q190.** Describe the TCP three-way handshake.
**Answer.** The client sends SYN with a sequence number, the server replies SYN-ACK with its own sequence and an acknowledgment, and the client sends ACK. This synchronizes sequence numbers before data flows.

**Q191.** Why is UDP used for DNS and why is it a DDoS risk?
**Answer.** UDP is connectionless and low-overhead, suitable for small DNS queries. Spoofed-source UDP requests to services that return larger responses enable amplification/reflection DDoS.

**Q192.** How does TLS provide confidentiality, integrity, and authentication?
**Answer.** Symmetric encryption with negotiated keys provides confidentiality; AEAD/MACs provide integrity; X.509 certificates validated against a trust store and hostname provide authentication.

**Q193.** What is the role of a reverse proxy and what security assumption can break?
**Answer.** It terminates TLS, routes, caches, and hides backend servers. Applications often trust forwarded headers added by the proxy; if a client can inject those headers directly, access controls can be bypassed.

**Q194.** How does traceroute work?
**Answer.** It sends packets with increasing TTL. Routers decrement TTL and return ICMP Time Exceeded when it reaches zero, revealing each hop's address.

**Q195.** What is NAT and what problem does it solve?
**Answer.** Network Address Translation maps private IP addresses to public ones, often with port translation. It conserves IPv4 addresses and hides internal topology, complicating peer-to-peer and some analysis.

**Q196.** What is the difference between a forward and reverse proxy?
**Answer.** A forward proxy acts for clients (caching, filtering, anonymity); a reverse proxy acts for servers (TLS termination, load balancing, protection).

**Q197.** Why does BGP pose a security risk?
**Answer.** BGP lacks built-in origin authentication by default, so a false route announcement can redirect traffic through an attacker's network (route hijacking). RPKI aims to fix this.

**Q198.** What is DNS tunneling?
**Answer.** Encoding data in DNS query names or responses to exfiltrate information or establish covert channels, exploiting the fact that DNS is usually allowed through firewalls.

**Q199.** What does tcpdump filter syntax look like to capture HTTP on an interface?
**Answer.** `tcpdump -i any -nn 'tcp port 80'` captures TCP packets on port 80 with no name resolution; `-w file.pcap` saves them for Wireshark.

**Q200.** What is a socket?
**Answer.** The combination of IP address, port, and protocol that uniquely identifies an endpoint of a network connection.

**Q201.** What is certificate transparency and how is it useful for recon?
**Answer.** CT logs publicly record issued TLS certificates. Querying them reveals subdomains and hostnames for a domain without active scanning.

**Q202.** What is ICMP used for and how can it be abused?
**Answer.** ICMP provides diagnostics (ping, traceroute, unreachable). It can be abused for tunneling, reconnaissance, and amplification/SMURF-style attacks.

**Q203.** What is a stateful firewall?
**Answer.** A firewall that tracks the state of connections and permits return traffic for established sessions, rather than evaluating each packet in isolation.

**Q204.** What is IPv6 link-local address range and why is it security-relevant?
**Answer.** fe80::/10. SSRF defenses must block IPv6 loopback and link-local ranges as well as IPv4 private ranges, or attackers can bypass filters using IPv6 addresses.

**Q205.** What is a MITM attack and what enables it on a LAN?
**Answer.** An attacker secretly relays or alters communications. On a LAN, ARP spoofing or rogue DHCP can redirect traffic through the attacker; TLS with validated certificates defends against disclosure.

**Q206.** What is network segmentation and why does it matter?
**Answer.** Dividing a network into zones with controlled traffic flow limits lateral movement and blast radius after a compromise.

**Q207.** What is a DNS zone transfer and why can it be dangerous?
**Answer.** AXFR replicates DNS zone data between nameservers. If misconfigured to allow arbitrary clients, it can disclose all hostnames in a zone.

**Q208.** How does DHCP DORA work?
**Answer.** Discover (client broadcasts), Offer (server offers config), Request (client requests), Acknowledge (server confirms). A rogue DHCP server can supply malicious gateway/DNS settings.

**Q209.** What is an IP fragment and why is fragmentation relevant to evasion?
**Answer.** Large IP packets are split into fragments. Network devices may reassemble differently or fail to inspect later fragments, enabling evasion of filters or IDS.

**Q210.** What is TTL and how does it relate to TRACE and smuggling?
**Answer.** TTL limits packet lifetime. In HTTP, framing headers (Content-Length, Transfer-Encoding) determine request boundaries; disagreement — not TTL — enables smuggling. TTL is used in traceroute.

**Q211.** What is a VPN and what does it not protect against?
**Answer.** A VPN creates an encrypted tunnel over an untrusted network. It protects data in transit but does not make endpoints trustworthy or protect against application-layer attacks.

**Q212.** Why do proxies and load balancers complicate logging?
**Answer.** The backend sees the proxy's IP rather than the client's. Without trusted forwarded headers configured correctly, logs and access controls use the wrong identity.

**Q213.** What is port scanning and what is SYN (half-open) scanning?
**Answer.** Probing ports to find listening services. SYN scanning sends SYN, and a SYN-ACK indicates an open port without completing the handshake, making it stealthier and faster.

**Q214.** What is the difference between MAC and IP addresses?
**Answer.** MAC addresses identify interfaces on a local link (layer 2); IP addresses identify hosts on an internetwork (layer 3) and are used for routing.

**Q215.** What is an anycast address used for?
**Answer.** A single IP address routed to multiple locations; used by DNS roots and CDNs to direct clients to a nearby or healthy instance.

**Q216.** What is a stack buffer overflow and why is the return address important?
**Answer.** Writing beyond a stack buffer can overwrite the saved return address. When the function returns, execution jumps to the attacker's chosen address, giving control of the instruction pointer.

**Q217.** What is a use-after-free?
**Answer.** Continuing to use a pointer after its memory has been freed. If the memory is reallocated with attacker-controlled data, the dangling pointer can be used for arbitrary reads or writes.

**Q218.** What is a format string vulnerability?
**Answer.** Passing user-controlled data as a printf format string. Specifiers such as %x can leak stack values and %n can write memory, enabling reads and writes.

**Q219.** What is a double free?
**Answer.** Freeing the same allocation twice corrupts allocator metadata and can be leveraged to create overlapping allocations and arbitrary writes.

**Q220.** How do ASLR and NX work together, and what is needed to bypass them?
**Answer.** ASLR randomizes addresses; NX marks data regions non-executable. Bypass typically requires an information leak to defeat ASLR and code reuse such as ROP to defeat NX.

**Q221.** What is a stack canary?
**Answer.** A random value placed before the return address and checked on function return. Overflowing the buffer alters the canary, causing detection before the return address is used.

**Q222.** What is ROP in one sentence?
**Answer.** Chaining short existing instruction sequences ending in `ret` (gadgets) to perform arbitrary operations despite non-executable memory.

**Q223.** What is CFI and what attack does it hinder?
**Answer.** Control-Flow Integrity restricts indirect branches to a set of valid targets, hindering ROP and other control-flow hijacking attacks.

**Q224.** What is an ELF file and which tools inspect it?
**Answer.** The Executable and Linkable Format used on Linux. Tools include readelf, objdump, nm, file, and debuggers like GDB.

**Q225.** What is the difference between disassembly and decompilation?
**Answer.** Disassembly translates machine code to assembly instructions; decompilation attempts to reconstruct higher-level source-like code. Decompiler output is approximate and should be verified.

**Q226.** Why is compiler optimization relevant to binary analysis?
**Answer.** Optimization can reorder, inline, or eliminate code, so source-level structures may not map neatly to the binary; decompiled output may differ substantially from the original source.

**Q227.** What does `checksec` report?
**Answer.** Which exploit mitigations a binary has: RELRO, stack canary, NX, PIE/ASLR, and other protections.

**Q228.** What is a coverage-guided fuzzer?
**Answer.** A fuzzer that instruments the target and keeps inputs that reach new code paths, using coverage feedback to explore the input space efficiently.

**Q229.** What does AddressSanitizer detect?
**Answer.** Memory errors such as use-after-free, heap and stack buffer overflows, double free, and some leaks, at the cost of overhead.

**Q230.** What is crash minimization and why is it useful?
**Answer.** Reducing a crashing input to the smallest reproducer. It makes root-cause analysis and reporting easier and removes unrelated noise.

**Q231.** What is a fuzzing harness?
**Answer.** A small program that takes fuzzer-generated bytes and calls the target function in a deterministic, resettable way, isolating the code under test.

**Q232.** What is the difference between mutation-based and grammar-based fuzzing?
**Answer.** Mutation-based fuzzing alters existing seed inputs; grammar-based fuzzing generates inputs from a specification of the format, producing structurally valid test cases.

**Q233.** What is differential fuzzing?
**Answer.** Feeding the same inputs to two implementations and comparing outputs to find logic discrepancies or bugs in one implementation.

**Q234.** What is a gadget in the context of deserialization attacks?
**Answer.** A class/method chain within available libraries that an attacker can trigger during deserialization to produce a side effect such as command execution.

**Q235.** Why are many crashes not security vulnerabilities?
**Answer.** Some crashes are benign assertion failures or null dereferences with no attacker control or impact. Exploitability requires demonstrating controlled influence and meaningful consequences.

**Q236.** What is a PE file and which sections are common?
**Answer.** The Windows Portable Executable format. Common sections include .text (code), .data/.rdata (data), .rsrc (resources), and import/export tables.

**Q237.** What is the shared responsibility model?
**Answer.** The cloud provider secures the cloud infrastructure (physical, hypervisor, network), while the customer secures data, identities, configurations, and workloads in the cloud. The split varies by IaaS/PaaS/SaaS.

**Q238.** Why are temporary credentials preferred over long-lived access keys?
**Answer.** They expire automatically and are scoped, reducing the window of misuse if leaked. Long-lived keys in source or laptops are a common initial-access vector.

**Q239.** What is IMDSv2 and how does it mitigate SSRF?
**Answer.** AWS Instance Metadata Service v2 requires a token obtained via a PUT request with a header, so a simple SSRF GET cannot retrieve instance credentials.

**Q240.** What is a public bucket misconfiguration?
**Answer.** Object storage with public read or write access via ACLs or policies. It exposes data or allows attackers to host malicious content. Fix with private defaults and policy checks.

**Q241.** What is BOLA in API security?
**Answer.** Broken Object Level Authorization: the API accepts an object identifier but fails to verify the caller owns or may access that object — effectively IDOR for APIs.

**Q242.** What is mass assignment in an API?
**Answer.** Binding request fields directly to a model so an attacker can set unintended properties such as role or balance. Fix with explicit writable-field allow-lists.

**Q243.** What is GraphQL introspection and when is it a problem?
**Answer.** A feature that exposes the schema. It is a problem when it reveals sensitive fields or accelerates attacks to unauthenticated users; disable or authenticate it in production.

**Q244.** How do rate limits protect APIs?
**Answer.** They limit brute-force attempts, credential stuffing, enumeration, and resource exhaustion. They must be enforced per account/IP/token and be hard to bypass with header spoofing.

**Q245.** What is dependency confusion?
**Answer.** Publishing a malicious public package with the same name as an internal package and a higher version so a build fetches the public one. Prevent with scoped namespaces and registry pinning.

**Q246.** What is an SBOM and why does it help?
**Answer.** A Software Bill of Materials is a machine-readable inventory of components. When a new CVE appears, you can query the SBOM to see which products are affected.

**Q247.** What is a Kubernetes network policy?
**Answer.** A resource controlling traffic between pods. A default-deny policy limits lateral movement if a pod is compromised.

**Q248.** What is the danger of a mounted Docker socket?
**Answer.** Access to /var/run/docker.sock effectively grants control of the Docker daemon and often the host, enabling privilege escalation and container escape.

**Q249.** What does signing build artifacts provide?
**Answer.** It proves the artifact's origin and integrity, so deployment can verify it was produced by the expected pipeline and not tampered with.

**Q250.** What is a deep link vulnerability in mobile apps?
**Answer.** An app trusts unvalidated parameters from a custom URL scheme, enabling navigation to internal screens, WebView loading of attacker pages, or data exposure.

**Q83.** What is RAG and what is its central security issue?
**Answer.** Retrieval-Augmented Generation retrieves external documents and includes them in the prompt. The security issue is that retrieved content is untrusted and can carry indirect prompt injection or leak across tenants.

**Q84.** How do you test RAG tenant isolation safely?
**Answer.** Seed unique marker documents in each of your own tenants, then query as one tenant for the other's marker. If the marker is retrieved or appears in the answer, isolation is broken.

**Q85.** What is excessive agency in LLM systems?
**Answer.** Granting an AI system more functionality, permissions, or autonomy than needed. Manipulated or erroneous outputs can then trigger damaging tool actions.

**Q86.** Where should authorization be enforced in an agentic system?
**Answer.** In deterministic code outside the model, in a policy gate that validates every proposed tool call against the user's permissions. The model's decision alone is not a security control.

**Q87.** What is unbounded consumption?
**Answer.** Resource and cost exhaustion of an AI system via long inputs, huge retrieval sets, recursive agent loops, or many requests. Mitigate with token, time, concurrency, and cost limits.

**Q88.** What is training data poisoning?
**Answer.** Injecting malicious examples into training or fine-tuning data to create backdoors, bias, or misbehavior in the resulting model.

**Q89.** What is model extraction?
**Answer.** Querying a model API extensively to reconstruct a substitute model or recover information about its parameters and training data.

**Q90.** What is membership inference?
**Answer.** Determining whether a particular record was part of a model's training set by analyzing output differences.

**Q91.** What is an embedding and how can embeddings create risk?
**Answer.** A numeric vector representing semantic meaning. Risks include cross-tenant retrieval if metadata filters are missing, poisoning of vector stores, and possible inversion to recover content.

**Q92.** What is an insecure MCP server?
**Answer.** A Model Context Protocol server exposing tools with excessive scope, missing authentication, or injection flaws in tool handlers, enabling unauthorized actions or RCE.

**Q93.** Which OWASP list governs an LLM used as a component versus an autonomous agent?
**Answer.** The OWASP Top 10 for LLM Applications governs model-as-component risks; the OWASP Top 10 for Agentic Applications covers agents that plan and act. Use both for agentic systems.

**Q94.** What is a cross-modal prompt injection?
**Answer.** Hiding instructions in a non-text modality, such as text rendered in an image or spoken audio, that the multimodal model interprets as instructions.

**Q95.** What does LLM08:2026 Hidden Context Exposure cover?
**Answer.** It broadens the former System Prompt Leakage category to cover exposure of hidden context — system prompts, configuration, or other information that should remain out of reach.

**Q96.** Why must tool outputs be treated as untrusted?
**Answer.** An attacker may control a web page, file, or API response that a tool returns; if the agent treats it as instructions, it can be steered into unauthorized actions.

**Q97.** What is memory poisoning in agents?
**Answer.** Inserting malicious content into an agent's persistent memory so it influences behavior in later sessions.

**Q98.** What is a measurable impact for an AI security finding?
**Answer.** An unauthorized data read, an unintended high-impact tool call, a tenant boundary crossing, or another outcome with consequences beyond the model's text output.

**Q99.** Name three AI security tools and their purpose.
**Answer.** Garak scans LLMs for vulnerabilities; PyRIT supports adversarial AI red teaming; Promptfoo runs prompt evaluation and red-team test cases.

**Q100.** What is the role of a deterministic policy gate in an agent?
**Answer.** It evaluates each proposed tool call against authorization policy and blocks disallowed actions regardless of what the model requested, providing a non-probabilistic security boundary.
