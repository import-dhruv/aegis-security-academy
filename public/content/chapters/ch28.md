# Chapter 28: Build Your Own Cybersecurity Research Laboratory

> **Learning objectives.** Build an isolated, reproducible lab with VMs, Docker, proxy tools, vulnerable apps, local DNS, and evidence management — and keep it safely separated from production.

## 28.1 Lab Design Principles

- **Isolation:** the lab must not be able to harm other systems. Use host-only or NAT networks, dedicated VMs, and no credentials to real accounts.
- **Reproducibility:** use Docker Compose and snapshots so environments can be rebuilt.
- **Safety:** install tools on the lab machine, not on a work production machine; use a separate browser profile for lab traffic.
- **Evidence:** keep a structured directory for captures, logs, and notes.

## 28.2 Host and Virtualization

Recommended base:

- **Host:** Ubuntu 22.04/24.04 LTS or a dedicated machine with at least 16 GB RAM.
- **Virtualization:** VirtualBox or VMware Workstation.
- **VMs:**
  - Kali Linux (attacker machine: Burp, ZAP, Wireshark, Nmap, Python).
  - Ubuntu Server (target machine: vulnerable apps via Docker).
  - Optional Windows eval VM for Windows-specific tooling.

Network modes:

- **NAT:** VMs can reach the internet but are not reachable from outside — good for the attacker VM.
- **Host-only / Internal network:** isolated VM-to-VM network for targets.
- Never bridge a vulnerable lab app directly to a network with untrusted hosts.

## 28.3 Docker and Vulnerable Applications

Install Docker and Docker Compose. Use official images where possible. A sample Compose file:

```yaml
version: "3.8"
services:
  juice-shop:
    image: bkimminich/juice-shop
    ports: ["3000:3000"]
  dvwa:
    image: vulnerables/web-dvwa
    ports: ["8081:80"]
  webgoat:
    image: webgoat/webgoat-8.0
    ports: ["8082:8080"]
```

Always pull images from trusted sources and run them only in the lab network.

## 28.4 Tool Installation

- **Kali:** most tools preinstalled; `sudo apt update && sudo apt install <tool>`.
- **Burp Suite:** https://portswigger.net/burp (install CA cert in lab browser).
- **OWASP ZAP:** https://www.zaproxy.org/download/
- **Wireshark:** `sudo apt install wireshark`.
- **Python venv:** `python3 -m venv ~/venvs/security && source ~/venvs/security/bin/activate`, then `pip install requests dnspython beautifulsoup4`.
- **Go tools:** install Go, then `go install ...` for Subfinder/httpx/ffuf (Chapter 16).

## 28.5 Local DNS and Hosts

Use `/etc/hosts` (lab machine) or a local DNS server (dnsmasq) to map lab names:

```
127.0.0.1   juice.lab.test
192.168.56.10  dvwa.lab.test
```

This lets you practice Host-header and virtual-host techniques safely.

## 28.6 Test Accounts

Create a small set of labeled accounts per lab app:

```
lab-user-a@lab.test / Password123!
lab-user-b@lab.test / Password123!
lab-admin@lab.test  / (only in your own app)
```

Never reuse real passwords. Keep accounts in a password manager or an encrypted note.

## 28.7 Logging and Evidence Management

Directory structure:

```
~/labs/
  juice-shop/
    notes.md
    captures/
    reports/
    scripts/
  dvwa/
    ...
```

Record: date, app version, steps, request/response files, screenshots, and conclusions. Use `script` or terminal recording if desired; keep timestamps.

## 28.8 Learning Platforms

| Platform | Type | Focus |
|----------|------|-------|
| OWASP Juice Shop | Vulnerable app | Modern web vulnerabilities, gamified |
| DVWA | Vulnerable app | Classic web vulns at several levels |
| WebGoat | Training app | Guided OWASP lessons |
| PortSwigger Web Security Academy | Free online labs | Deep web security, excellent |
| TryHackMe | Guided platform | Broad, beginner-friendly |
| Hack The Box Academy | Guided platform | Intermediate/advanced |
| picoCTF | CTF | Beginner-friendly broad challenges |
| OverTheWire | CTF | Linux, binary basics (Bandit, Narnia) |
| OWASP crAPI | Vulnerable app | API security |

Use official sites and follow their setup instructions. Each has learning objectives and progressive exercises.

## 28.9 Progression

1. Set up Juice Shop and solve the "score board" challenges, writing notes.
2. Use PortSwigger Academy labs for each vulnerability class in Chapter 9.
3. Practice API testing on crAPI.
4. Practice binary basics on OverTheWire.
5. Build the Chapter 29 projects against your lab apps.
6. Move to TryHackMe/HTB paths for network and machine-based challenges.

## 28.10 Safety Checklist

```
[ ] Lab network is isolated (no bridging to untrusted networks).
[ ] Vulnerable apps are not exposed to the public internet.
[ ] No real credentials or personal data in the lab.
[ ] Snapshots taken before destructive exercises.
[ ] All scanning confined to lab IPs.
```

## 28.11 Key Takeaways

- A good lab is isolated, reproducible, and well documented.
- Use Docker for targets and VMs for separation.
- Official vulnerable apps and guided platforms provide structured progression.
- Keep evidence from day one — it becomes your portfolio.
