```bash
curl -v https://target; curl -I; curl -X POST -d 'a=b'; curl -H 'Host: x' URL

# Scanning (authorized targets only)
nmap -sV -sC -oA out target

# Path

```

## 36.4 Burp Suite Workflow Reference

1. **Configure proxy:** browser to `127.0.0.1:8080`; install CA certificate; confirm HTTPS interception.
2. **Set scope:** Target → Scope; include in-scope assets only; enable "And URL" filtering.
3. **Browse:** walk every workflow; populate the site map; use the browser's normal flows.
4. **Inspect:** Proxy/HTTP history; review parameters, cookies, headers; note interesting requests.
5. **Send to Repeater:** modify one parameter at a time; compare responses.
6. **Intruder (Pro) / manual:** enumerate identifiers with your own test accounts; rate-limit.
7. **Decoder/Comparer:** decode tokens; diff responses.
8. **Collaborator (Pro):** OOB detection for blind SSRF/XXE/injection in labs.
9. **Scanner (Pro):** passive always; active only on authorized targets; triage findings.
10. **Document:** export requests/responses into your journal and report.

## 36.15 Monthly Assessment Framework

1. **Knowledge check:** answer 20 questions from Chapter 34 without notes.
2. **Practical check:** solve one timed lab in your weakest area.
3. **Report check:** write one full report from a lab finding.
4. **Tool check:** improve or document one tool/script.
5. **Review:** update journal, roadmap, and next month's goals.

## 36.16 Responsible Disclosure Guide

1. Report privately to the vendor/program with reproducible details.
2. Use their preferred channel and encryption if offered.
3. Agree on a remediation timeline (commonly 30--90 days absent program terms).
4. Avoid public details, exploit code, or data dumps before a fix.
5. Coordinate publication; credit appropriately and respect confidentiality.
6. If unresponsive, consider a coordinator (e.g., national CERT) and follow the law.

## 36.17 Security Researcher Ethics Charter

- I will test only systems I own or have explicit written authorization to test.
- I will not access, modify, exfiltrate, or destroy other people's data.
- I will use synthetic data and my own accounts for demonstrations.
- I will avoid destructive, disruptive, or persistent actions.
- I will report findings responsibly and allow reasonable time for remediation.
- I will be accurate and honest in reports, including limitations.
- I will respect privacy, laws, and program rules at all times.
- I will use my skills to improve security, not to cause harm.

## 36.19 Complete Glossary

> 554 technical terms defined across the book.

- **Access control.** The set of policies and mechanisms that determine who may access or modify a resource.
- **ACL.** Access Control List; a list of permissions attached to an object or network device.
- **Address space.** The range of virtual memory addresses available to a process.
- **Advanced persistent threat (APT).** A prolonged, targeted intrusion campaign, often state-sponsored, aimed at sustained access.
- **Adversarial machine learning.** The study of attacks that deceive or manipulate ML models.
- **AEAD.** Authenticated Encryption with Associated Data; provides confidentiality and integrity together.
- **Agent (AI).** An AI system that plans, calls tools, and takes actions across multiple steps on behalf of a user.
- **Agentic AI.** AI systems that act as autonomous actors with memory and tools, as opposed to passive model components.
- **Aggregation.** Combining multiple data sources, sometimes exposing more than each alone.
- **Algorithm confusion.** Tricking a verifier into using a different algorithm than intended, e.g., RS256 to HS256.
- **Allow-list.** A list of explicitly permitted items; the preferred alternative to a deny-list.
- **ALU.** Arithmetic Logic Unit; the CPU component that performs arithmetic and logical operations.
- **Amass.** OWASP tool for attack-surface mapping and subdomain enumeration.
- **Anomaly detection.** Identifying behavior that deviates from a learned baseline.
- **Anti-CSRF token.** A per-session or per-request secret that validates the origin of a state-changing request.
- **Antivirus.** Software that detects and removes malware using signatures, heuristics, and behavioral analysis.
- **Apex domain.** The root domain of a DNS zone, e.g., example.com.
- **API.** Application Programming Interface; a defined way for software components to communicate.
- **API fuzzing.** Sending malformed or unexpected API requests to find bugs.
- **API gateway.** A service that centralizes routing, authentication, rate limiting, and observability for APIs.
- **API inventory.** A maintained list of all APIs, versions, and their owners.
- **ARP.** Address Resolution Protocol; maps IPv4 addresses to MAC addresses on a local network.
- **ARP spoofing.** Forging ARP replies to associate an attacker's MAC with another IP, enabling local MITM.
- **ASLR.** Address Space Layout Randomization; randomizes memory addresses to hinder exploitation.
- **Asymmetric encryption.** Encryption using a public/private key pair (e.g., RSA, ECC).
- **Attack chain.** A sequence of vulnerabilities or steps combined to achieve an impact.
- **Attack surface.** The sum of all points where an unauthorized user can interact with a system.
- **Attack tree.** A hierarchical diagram of ways an attacker might achieve a goal.
- **Attribute-based access control.** Authorization based on attributes of the subject, object, and environment.
- **Audit log.** A chronological record of security-relevant events.
- **Authentication.** Verifying the identity of a user or system.
- **Authentication bypass.** Gaining access without valid credentials by exploiting a logic or implementation flaw.
- **Authorization.** Determining what an authenticated identity is permitted to do.
- **Authorization code.** A short-lived OAuth credential exchanged for an access token.
- **Availability.** The property that systems and data are accessible when needed.
- **Backdoor.** A hidden mechanism that bypasses normal authentication or security controls.
- **Backoff.** Progressively increasing delays between retries to avoid overloading a service.
- **Backpropagation.** The algorithm used to compute gradients and update neural network weights during training.
- **Bandwidth.** The capacity of a network link, often measured in bits per second.
- **Bastion host.** A hardened host designed to be the single point of access to a network.
- **Bayesian inference.** Statistical inference updating beliefs with evidence; used in some security models.
- **Bcrypt.** A password-hashing function designed to be computationally expensive.
- **Behavioral biometrics.** Authentication based on patterns such as typing rhythm or mouse movement.
- **Bell-LaPadula.** A formal confidentiality model enforcing no-read-up and no-write-down.
- **Biba model.** A formal integrity model enforcing no-read-down and no-write-up.
- **Binary.** A number system with base 2, using digits 0 and 1.
- **Binary exploitation.** Finding and leveraging memory-corruption flaws in compiled programs.
- **Biometrics.** Authentication using physical characteristics such as fingerprints or face.
- **BIOS/UEFI.** Firmware that initializes hardware before the operating system boots.
- **Black-box testing.** Testing without knowledge of internal structure or source code.
- **Blacklist.** A list of explicitly blocked items; generally weaker than an allow-list.
- **Blind injection.** Injection where results are inferred via behavior rather than returned data.
- **Block cipher.** A symmetric cipher that encrypts fixed-size blocks of data (e.g., AES).
- **Blue team.** The defensive side of security operations.
- **BOLA.** Broken Object Level Authorization; failure to verify access to a specific object (IDOR).
- **Boolean-based injection.** Inference technique using true/false response differences.
- **Bootstrap.** The process by which a system initializes itself using minimal initial state.
- **Botnet.** A network of compromised machines controlled by an attacker.
- **Breadth-first search.** An algorithm exploring neighbors before deeper nodes; used in crawlers and graphs.
- **Brute force.** Trying many candidate values until one succeeds.
- **Buffer.** A region of memory used to hold data temporarily.
- **Buffer overflow.** Writing data beyond a buffer's allocated boundary, corrupting adjacent memory.
- **Burp Suite.** An integrated web application security testing platform from PortSwigger.
- **Business continuity.** Planning to maintain critical functions during and after a disruption.
- **Business logic vulnerability.** A flaw in workflow design that allows a disallowed outcome using legitimate functionality.
- **Byte order.** Endianness; the order in which bytes of a multi-byte value are stored.
- **C2.** Command and control infrastructure used to communicate with compromised hosts.
- **Cache key.** The set of request attributes used to identify a cached response.
- **Cache poisoning.** Causing a cache to store a malicious response that is served to other users.
- **Call stack.** A stack data structure storing active function call frames.
- **Canonicalization.** Converting data to a standard form before validation or comparison.
- **CAPTCHA.** A challenge used to distinguish humans from automated clients.
- **Certificate authority.** An entity that issues digital certificates after verifying identity.
- **Certificate pinning.** Restricting trusted certificates to a known set to defend against MITM.
- **Certificate transparency.** Public logs recording all issued TLS certificates.
- **ChaCha20.** A modern stream cipher often paired with Poly1305 for authenticated encryption.
- **Chained vulnerability.** See attack chain.
- **Challenge-response.** Authentication where one party presents a challenge and the other proves knowledge.
- **Checksum.** A value computed from data to detect accidental corruption.
- **Child domain.** A subdomain that is part of a parent DNS zone.
- **CIA.** See CIA triad.
- **CIA triad.** Confidentiality, Integrity, and Availability; the three core security goals.
- **CIDR.** Classless Inter-Domain Routing; IP address ranges written with a prefix length.
- **Ciphertext.** Encrypted data.
- **CIS benchmark.** A consensus set of configuration security recommendations.
- **Clickjacking.** Tricking a user into clicking a hidden or disguised element via overlays.
- **Client-server.** An architecture where clients request services from servers.
- **Clock skew.** Difference in time between systems, relevant to token validity and logs.
- **Cloud computing.** On-demand delivery of compute and storage resources over a network.
- **Cloud IAM.** Identity and access management services provided by cloud platforms.
- **Code injection.** Inserting code into a program through untrusted input.
- **Code review.** Systematic examination of source code for defects.
- **Code signing.** Digitally signing software to prove origin and integrity.
- **Collision.** Two different inputs producing the same hash output.
- **Column-store.** A database storing data by column rather than row, optimized for analytics.
- **Command and control.** See C2.
- **Command injection.** Executing arbitrary OS commands by inserting them into unsanitized input.
- **Common Crawl.** A public corpus of web crawl data useful for historical URL discovery.
- **Common name.** A certificate field historically used for hostname validation, now deprecated.
- **Comparative advantage.** In security economics, the benefit of specializing in a particular defensive or offensive activity.
- **Compensating control.** An alternative control used when the primary control is impractical.
- **Compiler.** A tool that translates source code into machine code or bytecode.
- **Compiler optimization.** Transformations a compiler applies to improve performance; can alter security behavior.
- **Compliance.** Adherence to laws, regulations, standards, or policies.
- **Computer forensics.** The practice of investigating digital evidence for legal or incident-response purposes.
- **Concurrency.** Multiple computations proceeding simultaneously.
- **Confidentiality.** The property that information is accessible only to authorized parties.
- **Configuration management.** Maintaining systems in a desired, known state.
- **Container.** A lightweight isolated process environment sharing the host kernel.
- **Container orchestration.** Automated management of container deployment, scaling, and networking.

- **Hydration.** The process by which a client-side framework attaches to server-rendered markup.
- **Hypervisor.** Software that creates and runs virtual machines.
- **IAM.** Identity and Access Management; controls over identities and their permissions.
- **ICS.** Industrial Control Systems used in critical infrastructure.
- **Identity federation.** Linking identities across multiple systems using a trusted third party.
- **IDOR.** Insecure Direct Object Reference; accessing objects by manipulating identifiers without authorization.
- **IDP.** Identity Provider; a service that authenticates users for relying parties.
- **IDS.** Intrusion Detection System; detects suspicious activity.
- **Immutability.** The property that an object cannot be changed after creation.
- **Implicit flow.** A deprecated OAuth flow that returned tokens in URL fragments.
- **In-band.** Data or control information carried within the same channel.
- **Incident.** An event that violates security policy or threatens assets.
- **Incident response.** The process of handling a security incident: contain, eradicate, recover, learn.
- **Indirect object reference.** A reference to an object whose meaning depends on context, e.g., a session-scoped cart ID.
- **Indirect prompt injection.** Prompt injection delivered via external content such as retrieved documents or web pages.
- **Inference.** Running a trained model to produce outputs for input data.
- **Inference attack.** Deriving private information from model outputs.
- **Information disclosure.** Exposing sensitive information to unauthorized parties.
- **Information security.** Protecting information regardless of medium.
- **Ingress filtering.** Controls on inbound traffic to a network.
- **Input validation.** Checking that input conforms to expected rules before use.
- **Insecure deserialization.** See insecure deserialization in the main glossary.
- **Instance metadata.** Data about a cloud instance available to the instance itself.
- **Integrity.** The property that data is accurate and unmodified without detection.
- **Integrity check.** A verification that data has not been altered.
- **Intermediate certificate.** A certificate chaining a leaf certificate to a root CA.
- **Intermediate representation.** A portable low-level representation used by compilers and VMs.
- **Interpreter.** A program that executes source code directly rather than compiling it ahead of time.
- **Intrusion prevention system.** A device that blocks detected malicious traffic.
- **IPv4.** Internet Protocol version 4 using 32-bit addresses.
- **IPv6.** Internet Protocol version 6 using 128-bit addresses.
- **Issuer.** The entity that issued a token or certificate and is identified by the iss claim.
- **Jailbreak (AI).** A prompt technique that bypasses a model's safety behavior.
- **JavaScript.** A programming language executed in browsers and on servers via Node.js.
- **JSON Web Key.** A JSON structure representing a cryptographic key, often used with JWTs.
- **JWT.** JSON Web Token; a signed, Base64URL-encoded token carrying claims.
- **Kali Linux.** A Debian-based distribution preloaded with security tools.
- **Kerberos.** A network authentication protocol using tickets and symmetric cryptography.
- **Kernel.** The core of an operating system, managing hardware and system resources.
- **Kernel mode.** A privileged CPU mode where code has unrestricted hardware access.
- **Key derivation function.** A function that derives one or more keys from a secret and other parameters.
- **Key exchange.** A method for two parties to establish a shared secret over an insecure channel.
- **Key management.** The processes for generating, storing, rotating, and destroying keys.
- **Key stretching.** Repeated hashing to increase the cost of password guessing.
- **Lateral authentication.** Authenticating to services on the same network with captured credentials.
- **Lateral movement.** Moving from one compromised system to others in a network.
- **Least agency.** The principle of giving AI agents only the autonomy necessary for the task.
- **Least privilege.** Granting only the permissions necessary to perform a task.
- **LFI.** Local File Inclusion; including local files via untrusted input.
- **Library.** A collection of reusable code linked into programs.
- **Load balancer.** A device that distributes requests across multiple servers.
- **Local file inclusion.** See LFI.
- **Local storage.** Browser API for persistent origin-scoped key/value storage.
- **Log injection.** Inserting forged entries into logs via untrusted input.
- **Logging.** Recording events for monitoring, auditing, and investigation.
- **Logic bomb.** Code that triggers a malicious action when a condition is met.
- **MAC address.** A 48-bit hardware address used on local networks.
- **Machine learning.** Algorithms that improve at a task through data rather than explicit programming.
- **Magic bytes.** Signature bytes at the start of a file identifying its format.
- **Malicious insider.** An authorized user who abuses their access.
- **Malware.** Software designed to harm or exploit systems.
- **Managed service provider.** A third party that manages IT services for other organizations.
- **Mandatory access control.** Access control enforced by a central policy regardless of object owner.
- **Mass assignment.** See mass assignment in main glossary.
- **MD5.** An obsolete hash function vulnerable to collisions.
- **Memory corruption.** Altering memory in unintended ways, often through pointer errors.
- **Memory leak.** Memory allocated but never released, causing increasing usage.
- **Memory safety.** The property that a program cannot access memory outside its intended allocations.
- **Metadata filtering.** Restricting vector or database queries to records matching an access-control attribute.
- **Metadata service.** A cloud service providing instance information and temporary credentials.
- **Microarchitecture.** The hardware implementation of an instruction set architecture.
- **Microservice.** An architectural style composing an application from small, independent services.
- **Middleware.** Software layer between the OS and applications, or between web server and app logic.
- **Minimization.** Reducing a reproducer to the smallest form that still triggers the bug.
- **MITM.** Man-in-the-Middle; an attacker secretly relaying or altering communications.
- **MITRE ATT&CK.** A knowledge base of adversary tactics and techniques.
- **Model poisoning.** Corrupting a model through malicious training or fine-tuning data.
- **Multi-factor authentication (MFA).** Requiring two or more authentication factors.
- **Multi-tenant.** An architecture where multiple customers share the same infrastructure with logical isolation.
- **Mutation testing.** Testing by introducing small changes to inputs or code.
- **Mutual TLS.** TLS where both client and server present certificates.
- **Namespace.** A kernel feature isolating a category of system resources.
- **NAT.** Network Address Translation; mapping private addresses to public ones.
- **Natural language processing.** The field of computing with human language, foundational to LLMs.
- **Network address.** An IP address identifying a network rather than a host.
- **Network segmentation.** See network segmentation in main glossary.
- **Network topology.** The arrangement of nodes and links in a network.
- **Nmap.** A network discovery and security scanning tool.
- **Non-repudiation.** Assurance that an action cannot be denied, typically via signatures and logs.
- **Nonce.** A number used once, often to prevent replay.
- **NOP sled.** A sequence of no-operation instructions used in older exploitation techniques.
- **Null byte.** A zero byte used as a string terminator in C; relevant to some path bypasses.
- **OAuth 2.0.** An authorization framework for delegated access.
- **Object-level authorization.** See BOLA.
- **OIDC.** OpenID Connect; an identity layer on top of OAuth 2.0.
- **One-time pad.** An unbreakable cipher when the key is truly random, as long as, and never reused.
- **Opaque token.** A token whose meaning is known only to the issuing server.
- **Open redirect.** A flaw allowing a parameter to control a redirect to an external site.
- **Origin.** The combination of scheme, host, and port used in browser security decisions.
- **Output encoding.** Converting data into a safe form for a specific output context.
- **OWASP.** Open Web Application Security Project; a nonprofit security community.
- **Packet.** A unit of data transmitted over a network.
- **Padding.** Extra bytes added to data to meet a block size or conceal lengths.
- **Parallel fuzzing.** Running multiple fuzzer instances across cores to increase throughput.
- **Parameter pollution.** Supplying duplicate parameters to exploit inconsistent parsing.
- **Parameterized query.** See parameterized query in main glossary.
- **Partitioning.** Dividing data or systems into isolated parts.
- **Passive reconnaissance.** Gathering information without directly interacting with the target.
- **Password hashing.** Storing passwords as salted, slow hashes (e.g., Argon2id, bcrypt).
- **Password spray.** Trying a small set of common passwords across many accounts.
- **Patch management.** The process of applying security updates systematically.
- **Path traversal.** Using relative path sequences to access files outside a directory.
- **Payload.** The part of an exploit that performs the intended action.
- **Payload splitting.** Dividing a malicious prompt into parts to evade filters.
- **Penetration test.** See penetration testing.
- **Penetration testing.** See penetration testing in main glossary.
- **Perfect secrecy.** The property that ciphertext reveals no information about the plaintext, achieved by a one-time pad.
- **Performance testing.** Testing responsiveness and stability under load.
- **Permission.** An authorization to perform a specific operation on a resource.
- **Permission model.** The rules by which a platform grants capabilities to applications.
- **Persistent XSS.** See stored XSS.
- **Phishing.** Deceptive attempts to obtain credentials or information.
- **Phishing kit.** A packaged set of files used to run phishing campaigns.
- **PIN.** A short numeric personal identification number.
- **Pivoting.** Using a compromised host to reach other networks.
- **Plaintext.** See plaintext in main glossary.
- **Pointer.** A variable holding a memory address.
- **Pointer arithmetic.** Computing memory addresses by adding offsets to pointers.
- **Policy engine.** A component that evaluates rules to make authorization decisions.
- **Port.** A numeric identifier for a network service on a host.
- **Port scanning.** Probing TCP/UDP ports to discover listening services.
- **Post-exploitation.** Actions taken after initial access is achieved.
- **PostMessage.** An API for cross-origin messaging that requires origin validation.
- **Powershell.** A Windows scripting shell commonly used by administrators and attackers.
- **Pre-authentication.** Access or actions available before identity verification.
- **Prefetch.** Loading a resource before it is needed, which can trigger unintended requests.
- **Preflight request.** An OPTIONS request checking CORS permission before a non-simple request.
- **Principle of least authority.** See least privilege.
- **Private key.** The secret half of an asymmetric key pair.
- **Privilege.** An authorized level of access or capability.
- **Privilege escalation.** Gaining higher privileges than authorized.
- **Privilege separation.** Dividing a system into components, each with the minimum privileges needed.
- **Prompt injection.** Manipulating an LLM through untrusted text that alters its instructions or behavior.
- **Proof of concept.** A demonstration that a vulnerability exists and is exploitable.
- **Protocol.** A set of rules governing communication between systems.
- **Prototype pollution.** Injecting properties into JavaScript object prototypes via unsafe merges.
- **Proxy.** An intermediary that relays requests between clients and servers.
- **Proxying.** Forwarding requests through an intermediary.
- **Public key.** The non-secret half of an asymmetric key pair, used for encryption or verification.
- **Public key infrastructure.** The system of CAs, certificates, and revocation that enables trusted key distribution.
- **Public suffix.** A domain under which independent registrants can create domains, e.g., .com or .co.uk.
- **Query parameter.** A key/value pair appended to a URL after a question mark.
- **Race condition.** A bug arising from timing-dependent interleaving of concurrent operations.
- **Race window.** The interval during which a race condition can be triggered.
- **Ransomware.** Malware that encrypts data and demands payment for restoration.
- **Rate limiting.** Restricting how many requests a client may make in a time window.
- **RCE.** Remote Code Execution; running arbitrary code on a remote system.
- **Rebinding.** See DNS rebinding.
- **Reconnaissance.** The phase of gathering information about a target.
- **Red team.** An adversarial team that emulates real attackers in authorized exercises.
- **ReDoS.** Regular Expression Denial of Service via catastrophic backtracking.
- **Reflection.** Using a proxy or third party to hide the source of traffic.
- **Regex.** See regular expression.
- **Regression testing.** Re-testing after changes to ensure prior behavior still holds.
- **Regular expression (regex).** A pattern language for matching text; can cause ReDoS if misused.
- **Relaying.** Forwarding authentication or messages between parties, sometimes maliciously.
- **Remote code execution.** See RCE.
- **Replay attack.** Capturing and re-sending a valid message to produce an unauthorized effect.
- **Repudiation.** Denying that an action occurred; countered by logging and signatures.
- **Resource exhaustion.** Consuming a resource (CPU, memory, disk, money) until service fails.
- **Response header.** An HTTP header sent by a server in a response.
- **Rest.** Representational State Transfer; an architectural style for web APIs using HTTP semantics.
- **Reverse engineering.** Understanding a system's structure and behavior from its artifacts.
- **Reverse proxy.** A proxy that sits in front of servers, hiding their identity and providing services.
- **Revocation.** Invalidating a certificate or token before its natural expiry.
- **Risk.** The potential for loss given threats, vulnerabilities, and impacts.
- **Risk assessment.** The process of identifying and evaluating risks.
- **Robustness principle.** Be conservative in what you send, liberal in what you accept; a source of parsing inconsistencies.
- **Role-based access control.** Authorization based on assigned roles.
- **Root.** The superuser account on Unix-like systems with full privileges.
- **Root cause.** The underlying reason a vulnerability exists.
- **Root of trust.** A trusted component from which security guarantees are derived.
- **ROP.** Return-Oriented Programming; chaining existing code gadgets to execute arbitrary logic.
- **Router.** A device forwarding packets between networks.
- **RSA.** A widely used asymmetric cryptosystem.
- **Runtime application self-protection.** Security checks embedded in the application runtime.
- **S3.** Amazon Simple Storage Service; object storage commonly misconfigured.
- **Salt.** Random data added to a password before hashing to defeat precomputed attacks.
- **Sandbox.** An isolated environment for running untrusted code.
- **Sandbox escape.** Breaking out of an isolated execution environment.
- **Sanitization.** Cleaning or escaping untrusted data before use.
- **Scalar.** A single value, as opposed to an array or object.
- **Schema.** A formal description of data structure (e.g., for APIs or databases).
- **Schema poisoning.** Corrupting a schema or API definition to influence clients or tools.
- **Schema validation.** Checking data against a defined structure and types.
- **Scope.** The set of assets and tests authorized in an engagement or program.
- **Script kiddie.** A low-skill attacker relying on ready-made tools.
- **Search engine dorking.** Using search operators to find exposed resources.
- **Search engine optimization poisoning.** Manipulating search results to distribute malicious links.
- **Secret.** A sensitive credential such as a key, token, or password.
- **Secure coding.** Writing software resistant to exploitation.
- **Secure element.** A dedicated hardware component for storing secrets and performing crypto.
- **Secure SDLC.** Integrating security practices into the software development lifecycle.
- **Security advisory.** A vendor publication describing a vulnerability and remediation.
- **Security boundary.** A point where different trust levels meet.
- **Security by obscurity.** Relying on secrecy of implementation as a security control (weak).
- **Security control.** A measure that reduces risk.
- **Security engineering.** Building systems and controls that provide security properties.
- **Security misconfiguration.** Insecure or incomplete configuration of a system.
- **Security regression.** A change that reintroduces a previously fixed vulnerability.
- **Seed.** An initial input or value used to start a process, such as fuzzing or random generation.
- **Server-side.** Logic executed on the server rather than in the client.
- **Server-side template injection.** See template injection.
- **Session.** Server-side state associated with a user interaction.
- **Session fixation.** Forcing a victim to use an attacker-chosen session identifier.
- **Session hijacking.** Taking over a victim's session by stealing or predicting the session token.
- **Session token.** A value identifying a session, typically stored in a cookie.
- **Setuid.** A Unix permission bit that runs a program with the owner's privileges.
- **SHA-256.** A widely used cryptographic hash function from the SHA-2 family.
- **Shared responsibility.** The cloud model dividing security duties between provider and customer.
- **Shared secret.** A secret value known to two or more parties.
- **Shell.** A command-line interpreter providing an interface to the operating system.
- **Side channel.** Leaking information through indirect effects such as timing or power use.
- **Side-channel attack.** See side channel.
- **SIEM.** Security Information and Event Management; centralized log analysis and alerting.
- **Signature.** A cryptographic value proving authenticity and integrity.
- **Signature verification.** Checking a digital signature using a public key.
- **Single sign-on (SSO).** Authenticating once to access multiple systems.
- **Single-packet attack.** Sending concurrent requests in as few packets as possible to narrow race windows.
- **Single-use token.** A token invalidated immediately after first use.
- **SOC.** Security Operations Center; a team or facility monitoring security events.
- **Social engineering.** Manipulating people into revealing information or performing actions.
- **Socket.** See socket in main glossary.
- **Software composition analysis.** Automated identification of third-party components and their vulnerabilities.
- **Software supply chain.** The chain of dependencies, build systems, and distribution used to produce software.
- **Source code analysis.** See static analysis.
- **Spear phishing.** Targeted phishing aimed at a specific individual or organization.
- **Spoofing.** Impersonating another identity or source.
- **SQL.** Structured Query Language for relational databases.
- **SQL injection.** See SQL injection in main glossary.
- **SSRF.** Server-Side Request Forgery; inducing a server to make arbitrary requests.
- **Stack.** A LIFO memory region used for function frames and local variables.
- **Stack canary.** A random value placed before the return address to detect stack overflows.
- **Stack frame.** A block of stack memory for a single function call.
- **State machine.** A model of behavior as transitions between states.
- **Stateful firewall.** A firewall that tracks connection state rather than inspecting packets in isolation.
- **Stateful inspection.** Firewall filtering that tracks connection state.
- **Static analysis.** Analyzing code or binaries without executing them.
- **Static application security testing.** See static analysis.
- **Stored XSS.** XSS where the payload is persisted and served to other users.
- **Subdomain.** A domain that is part of a larger domain.
- **Subdomain takeover.** Claiming an external service referenced by a dangling DNS record.
- **Subject.** The entity requesting access to an object.
- **Subresource integrity.** A browser feature verifying fetched resources against a cryptographic hash.
- **Supply chain.** See software supply chain.
- **Supply chain attack.** Compromising a less-secure element of a supply chain to attack a target.
- **Symbol table.** A data structure mapping names to addresses in a binary.
- **Symbolic execution.** Analyzing programs by treating inputs as symbolic values and exploring paths.
- **Symmetric encryption.** Encryption using a single shared key (e.g., AES).
- **Syntax highlight.** Coloring source code by token type for readability.
- **System call.** The controlled interface between user programs and the kernel.
- **System call filter.** A mechanism such as seccomp restricting which syscalls a process can make.
- **Table.** A structured collection of rows and columns used to organize data in databases or documents.
- **Taint analysis.** Tracking untrusted data from sources to sinks.
- **Template injection.** Injecting template syntax into a template that is then rendered.
- **Temporary credentials.** Short-lived credentials issued by a service such as AWS STS.
- **Test account.** An account created solely for authorized testing with synthetic data.
- **Threat actor.** An individual or group that poses a threat.
- **Threat hunting.** Proactively searching for signs of compromise that automated tools missed.
- **Threat model.** A structured description of assets, adversaries, and assumed capabilities.
- **Time-based injection.** Inference using deliberate delays in responses.
- **TLS.** Transport Layer Security; the protocol providing confidentiality and integrity for network traffic.
- **TOCTOU.** Time-of-check to time-of-use; a race between validation and use.
- **Token.** A value representing authorization or identity; also a unit of text for LLMs.
- **Token binding.** Cryptographically binding a token to a client to prevent replay elsewhere.
- **Tokenization.** See tokenization in main glossary.
- **Traceroute.** A tool that maps the network path using TTL and ICMP.
- **Transport layer.** The network layer providing end-to-end communication (TCP/UDP).
- **Transport layer security.** See TLS.
- **Triage.** The process of evaluating incoming vulnerability reports.
- **Trojan.** Malware disguised as legitimate software.
- **Trust boundary.** A point where data passes between components with different trust levels.
- **Trusted computing base.** The set of components that must be trusted for a system's security.
- **Trusted platform module.** A hardware chip providing secure key storage and attestation.
- **Two's complement.** A method of representing signed integers in binary.
- **Type confusion.** Using a value as a different type than intended, often leading to memory errors.
- **Type juggling.** Exploiting loose type comparisons in dynamically typed languages.
- **Typosquatting.** Registering names similar to popular ones to deceive users or builds.
- **Unicode.** A character encoding standard supporting most of the world's writing systems.
- **Unicode normalization.** Converting Unicode text to a canonical form, important for consistent validation.
- **Uninitialized memory.** Memory containing unpredictable previous contents.
- **Untrusted input.** Data from outside a trust boundary that must not be assumed safe.
- **URL encoding.** Representing special characters in URLs with percent-escapes.
- **URL scheme.** The leading part of a URL identifying the protocol, e.g., https:.
- **User agent.** An HTTP header identifying the client software.
- **User enumeration.** Determining which usernames exist through observable differences.
- **User mode.** An unprivileged CPU mode restricting hardware and memory access.
- **Virtual host.** Multiple websites served from one IP address, distinguished by the Host header.
- **Virtual machine.** A software emulation of a computer running its own OS.
- **Virtual memory.** An abstraction giving each process a private address space backed by physical memory and disk.
- **Vulnerability.** A weakness that can be exploited to violate security policy.
- **Vulnerability disclosure.** The process of reporting and coordinating remediation of a vulnerability.
- **Vulnerability management.** The ongoing process of discovering, prioritizing, and remediating vulnerabilities.
- **Vulnerability scanner.** A tool that automatically detects known weaknesses.
- **WAF.** See WAF in main glossary.
- **Web application firewall.** See WAF.
- **Webhook.** An HTTP callback that delivers event data to a third-party endpoint.
- **WebSocket.** A protocol providing full-duplex communication over a single connection.
- **White-box testing.** Testing with full knowledge of source and architecture.
- **Whitelist.** An allow-list of permitted items; preferred over deny-lists.
- **Wildcard certificate.** A TLS certificate valid for all subdomains at one level.
- **Wildcard domain.** A DNS record or scope entry matching all subdomains at a level, e.g., *.example.com.
- **Wireshark.** A graphical network protocol analyzer.
- **Work factor.** The computational cost of an operation, especially in password hashing.
- **Write-up.** A detailed written explanation of a vulnerability, challenge, or research finding.
- **X.509.** The standard format for public key certificates.
- **XML parser.** Software that reads XML; dangerous when external entities are enabled.
- **XOR.** Exclusive OR; a bitwise operation used in cryptography and checksums.

- **Zone transfer.** A DNS mechanism (AXFR) to copy a zone; misconfiguration can leak all records.
